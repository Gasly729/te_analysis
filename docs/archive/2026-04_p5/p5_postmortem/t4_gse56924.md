## 根因

两个文件的命名格式为 `GSM_Type_SRR.fastq.gz`（**无 `_1` 端号后缀**），
是单端测序文件下载时未添加 `_1` 后缀的非标格式。

`stage_fastq.py` 的 glob pattern 强制要求：

```python
candidates = sorted(study_dir.glob(f"{gsm}_*_{srr}_{end}.fastq.gz"))
# end=1 时 pattern = "GSM1371468_*_SRR1257250_1.fastq.gz"
```

实际文件名不含 `_1`，故匹配失败，返回 `None`，计入 `missing`。

## 失败传导

由于 SRR1257250 是 Ribo-Seq 样本，staging 缺失导致 snakescale 触发
`download_fastq_files` 规则，从网络下载。下载时遇到 SSL 证书验证失败：

```
prefetch.2.9.6: connection failed - mbedtls_ssl_handshake returned -9984
  ( X509 - Certificate verification failed )
```

导致整个 GSE56924 pipeline 失败。

## 修复

源文件在磁盘上，只需为两个文件手动补建 symlink：

```bash
# SRR1257193 (RNA-Seq)
ln -s $(readlink -f data/raw/Homo_sapiens/GSE56924/GSM1371411_RNA-Seq_SRR1257193.fastq.gz) \
  vendor/snakescale/input/fastq/GSE56924/GSM1371411/SRR1257193_1.fastq.gz

# SRR1257250 (Ribo-Seq)
ln -s $(readlink -f data/raw/Homo_sapiens/GSE56924/GSM1371468_Ribo-Seq_SRR1257250.fastq.gz) \
  vendor/snakescale/input/fastq/GSE56924/GSM1371468/SRR1257250_1.fastq.gz
```

并修复 `stage_fastq.py` 以支持无 `_1` 后缀的命名格式（长期修复）。
